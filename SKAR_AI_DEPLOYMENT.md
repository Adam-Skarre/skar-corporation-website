# SKAR AI production activation

The website never stores or exposes an AI provider key. Live SKAR AI responses are generated by the Cloudflare Worker in `worker/skar-ai.js`.

## One-time repository settings

In **GitHub → Settings → Secrets and variables → Actions**, add these repository secrets:

- `CLOUDFLARE_API_TOKEN` — a Cloudflare token with Workers Scripts edit and Workers Routes edit access.
- `CLOUDFLARE_ACCOUNT_ID` — the Cloudflare account ID that owns the Worker.
- `OPENAI_API_KEY` — the production OpenAI project key used only by the Worker.

Never add secret values to source files, pull requests, screenshots, or browser code.

## Domain

`wrangler.toml` publishes the Worker at `api.skartech.com`. The `skartech.com` zone must be active in the same Cloudflare account so Wrangler can create and manage the custom domain. Confirm that `api.skartech.com` resolves publicly after deployment.

## Deploy and verify

Merge a change to `worker/**`, `wrangler.toml`, or the deployment workflow, or run **Deploy SKAR AI API** manually from GitHub Actions. A successful run will:

1. Confirm all three secrets are present.
2. Deploy the Worker and upload `OPENAI_API_KEY` as an encrypted Worker secret.
3. Verify `https://api.skartech.com/skar-ai` returns a healthy response.

Until production activation is complete, the website shows a clear service-unavailable message. It does not substitute a scripted or canned answer for the live model.

## Conversation behavior

The browser sends the active conversation to the Worker, which calls the OpenAI Responses API with the model configured by `OPENAI_MODEL`. The Worker keeps the OpenAI key server-side and asks the model to provide a concise, inspectable rationale for substantive answers without exposing private hidden chain-of-thought.
